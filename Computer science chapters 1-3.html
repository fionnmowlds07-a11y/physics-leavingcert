🤖 The Turing Machine & Foundations of Computing

A Turing Machine is a theoretical computing device proposed by Alan Turing in 1936. It has: an infinite tape divided into cells, a read/write head, a finite set of states, and a transition table. By reading symbols and changing state, it can compute anything computable. It is the mathematical model behind every modern computer.

A Turing Machine is like a very simple post-office worker on an infinitely long conveyor belt. They read the next package (cell), follow a rulebook (transition table), write on it, and move left or right. Simple rules, infinite power!

Turing-complete — any system or programming language capable of simulating a Turing machine, meaning it can carry out any computation given enough time and memory. Python, Java, C are all Turing-complete. (DEB 2023 asked this directly.)

Tracing a Turing Machine — State Transition Table

The 2022 exam had you trace a Turing machine. The table shows: Current State + Symbol Read → Write Symbol, then move Right (R) or Left (L), then new State.

Example: Tape starts as 0 1 1 0 B (B = blank), head starts at position 0, state S0. Transition rule: if S0 reads 0 → write 1, move R, stay S0; if S0 reads 1 → write 0, move R, stay S0; if S0 reads B → HALT.

This machine flips every bit!

State: S0 | Head at position 0

Turing Machine = Tape + Head + States + Transitions = "THST" → "The Hard Stuff Today" 😄

🤖 Artificial Intelligence & Machine Learning

AI has appeared on EVERY paper since 2022. Memorise these definitions exactly.

Artificial Intelligence (AI) — the branch of computer science concerned with building machines or programs that can perform tasks that would normally require human intelligence — such as recognising speech, making decisions, learning from experience, and solving problems.

🎯
Narrow AI
Designed for ONE specific task. All AI today is narrow AI. Examples: Siri, spam filters, chess engines, recommendation algorithms, face recognition.
🌐

Hypothetical AI with human-level reasoning across EVERY domain. Does not yet exist. Would be able to learn any task a human can. (2024 paper.)
📈

Creates NEW content (text, images, audio, video, code) based on patterns learned from training data. Examples: ChatGPT, Gemini, DALL-E, Midjourney. (2024 paper.)
👁️

AI that analyses, identifies and understands objects/faces in images or video. Confidence scores = how sure the model is. Used in medical imaging, self-driving cars, security.

Machine Learning — 3 Types

Machine Learning — a subset of AI in which systems learn from data and improve over time without being explicitly programmed for every case.

Traditional programming: tell the computer exactly what to do for every situation. Machine Learning: show it thousands of examples and let it figure out the rules itself — like training a dog with treats rather than writing out every command!

👩‍🏫 Supervised Learning
Trained on labelled data — you tell it the right answer for each example.
Spam filter (labelled as spam/not spam), image classifier (labelled cat/dog).
🔍 Unsupervised Learning
Finds hidden patterns or clusters in unlabelled data.
Customer segmentation, anomaly detection, recommendation systems finding similar users.
🎮 Reinforcement Learning
Learns from rewards and punishments — trial and error to maximise a score.
Game-playing AI (chess, Go, video games), robot navigation, autonomous driving.

S-U-R = Supervised (teacher gives answers), Unsupervised (no labels, finds patterns), Reinforcement (learns from rewards). "Students Usually Reward good learning!"

Bias in Machine Learning

Bias in ML occurs when a model's predictions systematically favour or disadvantage certain groups — usually because the training data was unrepresentative.

How to reduce bias: use diverse, balanced training data; audit models for fairness; include diverse teams in design; test across different demographics; use bias-detection tools.

2025 paper: State a benefit AND a limitation of AI in medical diagnosis. Benefit: faster/more consistent screening, detects patterns humans miss. Limitation: biased if trained on narrow demographics; "black box" lack of explainability; liability issues.

🌐 The Internet vs The World Wide Web

The Internet is the global network of interconnected computer networks — it is the hardware infrastructure (cables, routers, servers).

The Internet carries: email, FTP, video calls, online gaming, the Web, and more.

The World Wide Web (WWW) is a service that runs on the Internet — an interconnected collection of websites and pages accessed via HTTP/HTTPS using browsers.

The Web is just ONE application that uses the Internet.

The Internet is like the road network — the physical infrastructure. The World Wide Web is like Google Maps — a service that uses those roads. You can also drive to a friends house (email) on the same roads without using Maps!

Internet = Infrastructure (the roads). Web = One service on those roads. "Internet is Infrastructure. Web is one Way to use it."

🔢 Binary, Decimal & Hexadecimal — Number Systems

Computers use binary (base 2) because transistors have exactly two states: ON (1) and OFF (0). This maps perfectly to physical electrical signals, making circuits simple and reliable.

Binary is like a row of light switches — each is either ON (1) or OFF (0). With 8 switches (1 byte) you can make 256 different patterns (0–255). More switches = more numbers you can represent!

Binary → Decimal: Place Value Method

Every bit position has a value that doubles as you go left. 8-bit place values:

Position2⁷2⁶2⁵2⁴2³2²2¹2⁰
Value1286432168421

Example: 11001001 = 128+64+0+0+8+0+0+1 = 201

Decimal → Binary: Repeated Division by 2

  1. 1
    Divide the decimal by 2. Write down the remainder (0 or 1).
  2. 2
    Divide the quotient by 2 again. Write down the remainder.
  3. 3
    Repeat until the quotient is 0.
  4. 4
    Read the remainders bottom to top — that's your binary number!

Example: 13 ÷ 2 = 6 R1 → 6 ÷ 2 = 3 R0 → 3 ÷ 2 = 1 R1 → 1 ÷ 2 = 0 R1 → Read bottom-up: 1101

Divide by 2 and collect remainders — then read upwards! Like reading a stack of papers from the bottom.

Hexadecimal (Base 16)

Hexadecimal is a base-16 system using digits 0–9 and letters A–F (where A=10, B=11, C=12, D=13, E=14, F=15). It is used as a compact shorthand for binary — every byte = exactly 2 hex digits.

Hex is like a shorthand language for binary. Writing FF is easier than 11111111. That's why colour codes (#FF5733), memory addresses, and MAC addresses use hex — fewer mistakes, easier to read!

Group binary into nibbles (groups of 4) from the right, then convert each nibble to one hex digit.

Example: 10110101 → 1011|0101 → B|5 → B5₁₆

Reverse: each hex digit expands to 4 binary bits. C9 → 1100 1001

Hex → Decimal (Exam Calculation!)

Multiply each hex digit by its place value (powers of 16).

Example C9₁₆: C = 12, 9 = 9.
(12 × 16¹) + (9 × 16⁰) = 192 + 9 = 201 ✅

Download Time Calculation

Download time formula: Time (s) = File size (MB) ÷ Transfer rate (MB/s). To convert Mbps to MB/s: divide by 8 (8 bits per byte).

Internet speed is measured in megabits per second (Mbps), but file sizes are in megabytes (MB). Since 1 byte = 8 bits, divide speed by 8 to get MB/s. Like converting km/h to m/s — different units, same thing!

Continuous vs Discrete Data

Continuous data can take ANY value within a range — including fractions and decimals. Examples: temperature, height, weight, speed, time.

Continuous = a dial (can be at any position). Temperature can be 20.5, 20.51, 20.512°C — infinite possible values between 20 and 21!

Discrete data can only take specific, separate values — usually whole numbers or categories. Examples: number of students, shoe sizes, number of cars.

Discrete = a light switch (on or off, nothing between). You can have 30 students or 31 students, but never 30.5 students!

Character encoding is a system that assigns a number (binary code) to every character (letter, digit, symbol) so computers can store and transmit text.

ASCII is a tiny local library — great for English books only. Unicode is the world's biggest library — every book in every language, plus emoji! But a bigger library needs a bigger building (more memory).

🔐 Cryptography & Cybersecurity

Caesar Cipher — Shift Cipher

A Caesar Cipher shifts every letter in the alphabet by a fixed number n. To decode: shift each letter backwards by n, wrapping around using modulo 26.

Decode formula: Decoded position = (letter_position − n) mod 26

Caesar cipher encode = shift forward n. Decode = shift backward n. Modulo handles the wrap-around (after Z comes A). DEB 2023 used shift n=7. HELLO shifted by 7 = OLSSV.

Pigpen Cipher

The Pigpen cipher uses two key grids — a # grid and an X grid — where each letter's position in the grid becomes its symbol (the shape of the segment it sits in).

To decode: match the shape of each symbol to the matching segment in the key diagram. Pure pattern recognition, no maths!

DEB 2024 asked you to decode a Pigpen message using a given key diagram. Strategy: look at the shape (the lines/corners), find which grid segment has that shape, and read the letter inside.

📈 Big O Notation — Algorithm Complexity

Big O notation describes the relationship between the size of the input (N) and the number of steps an algorithm takes. It measures the amount of work — NOT actual speed — and tells you how the algorithm scales as input grows.

Big O is like asking: "If I double the number of students in a class, how much longer does the roll-call take?" O(n) = twice as long. O(n²) = four times as long. O(log n) = barely any longer!

O(1)
Constant
Same steps no matter how big input is. Example: accessing a list by index.
O(log n)
Logarithmic
Halves the problem each step. Example: Binary Search.
O(n)
Linear
Steps grow with input. Example: Linear Search.
O(n log n)
Linearithmic
Good for sorting. Example: Quicksort (average), Mergesort.
O(n²)
Quadratic
Nested loops. Example: Bubble, Insertion, Selection Sort.

O(n²) Explained — What does it mean?

Input size (n)O(n²) operationsMeaning
5~255 × 5 = manageable
10~100Doubled input → 4x the work
100~10,000Starting to get slow
1,000~1,000,000Very slow!

Best → Worst: O(1) → O(log n) → O(n) → O(n log n) → O(n²)
"One Lucky ninja never needs n² ninjas!" 🥷

DEB 2024: "Sort these Big O complexities from best to worst." Answer: O(1) → O(log n) → O(n) → O(n log n) → O(n²). Also know which algorithm gives which: Binary Search = O(log n), Linear Search = O(n), Quicksort avg = O(n log n), Bubble/Insertion/Selection = O(n²).

🫧 Bubble Sort — O(n²)

Bubble Sort compares adjacent pairs and swaps them if they're in the wrong order. After each full pass, the largest unsorted element "bubbles up" to its correct position at the end.

Like bubbles rising in water — the biggest bubble always floats to the top first. After each pass, one more element is in its correct position at the end, and you never need to look at it again!

  1. 1
    Compare elements at positions [0] and [1]. If arr[0] > arr[1], swap them.
  2. 2
    Move to positions [1] and [2]. Compare and swap if needed.
  3. 3
    Continue to the end of the unsorted portion. After pass 1, the largest element is in its final position.
  4. 4
    Repeat, reducing the unsorted range by 1 each time.
  5. 5
    Optimisation: if a whole pass completes with zero swaps, the list is already sorted — stop early! This gives best case O(n).

Example: 5 passes on [50, 70, 30, 60, 20] — 2024 Exam!

PassList after passElement placed
Start[50, 70, 30, 60, 20]—
Pass 1[50, 30, 60, 20, 70]70 → end ✅
Pass 2[30, 50, 20, 60, 70]60 → position 4 ✅
Pass 3[30, 20, 50, 60, 70]50 → position 3 ✅
Pass 4[20, 30, 50, 60, 70]30 → position 2 ✅
Pass 5[20, 30, 50, 60, 70]Sorted! ✅

📌 Insertion Sort — O(n²)

Insertion Sort builds a sorted list one element at a time. Take the next unsorted element and insert it into its correct position in the already-sorted portion by comparing and shifting elements rightward.

Like sorting playing cards in your hand — you pick up a new card and slide it left into the right position among the cards you're already holding. Each new card finds its place!

  1. 1
    Start with the element at index 1 (element at index 0 is trivially "sorted").
  2. 2
    Compare this element (key) with the element to its left.
  3. 3
    If the left element is bigger, shift it right one position.
  4. 4
    Keep comparing leftwards, shifting larger elements right, until the correct position is found.
  5. 5
    Insert the key into the gap. Move to the next unsorted element.

Example: Bookshelf [7, 2, 4, 1, 5] — 2022 Exam Style!

PassKeyActionList after
122 < 7 → shift 7 right, insert 2[2, 7, 4, 1, 5]
244 < 7 → shift 7; 4 > 2 → insert[2, 4, 7, 1, 5]
311 < 7,4,2 → shift all; insert 1[1, 2, 4, 7, 5]
455 < 7 → shift 7; 5 > 4 → insert[1, 2, 4, 5, 7]

📌 Insertion = "Insert each card into its correct place in the hand". Best case = O(n) when already sorted (no shifts needed). Worst case = O(n²) when reverse sorted (maximum shifts).

Time ComplexityDetails
Best caseO(n) — already sorted, just one comparison per element
Average/Worst caseO(n²) — reverse sorted, maximum shifts each pass

🎯 Selection Sort — O(n²)

Selection Sort repeatedly finds the minimum value in the unsorted portion and places it at the start of that portion (by swapping). After each pass, one more element is in its final position.

Like a teacher picking the shortest student first and placing them at the front, then picking the next shortest, and so on. You're always selecting the smallest remaining item!

  1. 1
    Find the minimum value in the entire unsorted section (indices 0 to n-1).
  2. 2
    Swap it with the element at the current start position (index 0).
  3. 3
    Move the sorted boundary one position right. Now find the min in indices 1 to n-1.
  4. 4
    Repeat until fully sorted.

Example: [64, 25, 12, 22, 11]

PassMin foundSwapList after
111 (index 4)11 ↔ 64[11, 25, 12, 22, 64]
212 (index 2)12 ↔ 25[11, 12, 25, 22, 64]
322 (index 3)22 ↔ 25[11, 12, 22, 25, 64]
425 (index 3)already there[11, 12, 22, 25, 64]

🎯 "Selection = always Selecting the Smallest". Unlike bubble sort which moves things around a lot, selection sort makes exactly n-1 swaps total.

Always O(n²) regardless of input order — no best-case optimisation like bubble/insertion. 2022 paper gave a two-list version — know both in-place (swap) and two-list versions.

⚡ Quicksort — O(n log n) average, O(n²) worst

Quicksort is a divide-and-conquer algorithm. Choose a pivot element; partition the list into elements ≤ pivot (left) and elements > pivot (right); then recursively sort each partition.

Like organising a pile of books by price. Pick one book as a "pivot". Put all cheaper books on the left, all more expensive on the right. Now do the same thing separately on the left pile and right pile. Keep dividing until everything is sorted!

Pivot ≤ pivot > pivot

Tracing Quicksort — 2023 Exam: Pivot = 60 on [60,30,80,40,10,50,20,70,90]

  1. 1
    Choose pivot = 60.
  2. 2
    Left partition (≤ 60): [30, 40, 10, 50, 20]
  3. 3
    Right partition (> 60): [80, 70, 90]
  4. 4
    Result: [30,40,10,50,20] | 60 | [80,70,90]
  5. 5
    Recursively sort each partition until all single elements remain.

Why is 90 a bad pivot choice? — 2023 Exam!

If pivot = 90 (the maximum), left partition = all 8 other elements, right partition = empty. No meaningful split occurs — this degrades to O(n²) because we do n comparisons, then n-1, then n-2... same as Bubble Sort. Good pivot strategies: pick the median of first/middle/last elements, or a random element.

2025 Exam: Pivot = 13 on [29,10,14,37,13]

Worst caseO(n²) — when pivot is always the largest/smallest element

🔍 Binary Search — O(log n)

Binary Search finds a target in a sorted list by repeatedly halving the search space. Compare the target to the middle element: if equal = found; if target is smaller = search left half; if larger = search right half.

Like finding a name in a phone book — open to the middle, decide which half has the name, repeat. You never look at the wrong half again! Much faster than reading every page!

  1. 1
    Set low = 0, high = len(list) - 1.
  2. 2
    Calculate mid = (low + high) // 2.
  3. 3
    If list[mid] == target → return mid (found!).
  4. 4
    If target < list[mid] → set high = mid - 1 (search left half).
  5. 5
    If target > list[mid] → set low = mid + 1 (search right half).
  6. 6
    Repeat until found or low > high (not in list).
