Chapter 7: Networks & Protocols

How computers talk to each other — the internet, protocols, TCP/IP, topologies, and cybersecurity.

7

🌍 Internet vs World Wide Web EXAM

The Internet is the global network of connected computers and infrastructure that carries all data (web pages, emails, files, calls). It is hardware.

The World Wide Web (WWW) is a service that runs on top of the internet — it is the collection of web pages you view in a browser. The WWW is software / a service.

The internet is the road network — all the physical roads, motorways, and infrastructure. The WWW is like delivery trucks using those roads. Email, FTP, and video calls are other services using the same road network — not the road itself.

💡 Internet = Infrastructure (hardware). WWW = Web pages (service on that hardware). The web is a subset of what the internet can do. Not all internet use is web browsing!

A common exam trap: students say "internet" when they mean "web". Be precise — if you're talking about web pages, say WWW. If you're talking about the underlying connection, say internet.

📡 Network Types: LAN, WAN, PAN

LAN
Local Area Network

Covers a small area — one building, school, or office. Fast, private, cheap to run.

Example: School computer network

WAN
Wide Area Network

Covers large distances — cities, countries, the world. The internet is the biggest WAN.

Example: The internet itself

PAN
Personal Area Network

Very short range around one person — Bluetooth, USB connections.

Example: Phone + earphones via Bluetooth

Local = Little area  |  Wide = World  |  Personal = Pocket

🖥️ Client-Server vs Peer-to-Peer EXAM

🏢 Client-Server

A dedicated server stores all data and manages resources. Client computers send requests; server responds. Users must log in.

✅ Advantages: More secure, central backup, easy to manage, centralised control of access rights.

❌ Disadvantages: Expensive to set up and maintain. If server fails, ALL computers lose access.

👥 Peer-to-Peer (P2P)

All computers are equal peers — each can act as both client and server. Data is shared directly between devices.

✅ Advantages: Cheap, easy to set up. No single point of failure.

❌ Disadvantages: Less secure, hard to manage, data spread across many computers.

Client-Server is like a bank — all your money (data) is stored securely in one place (the server), and you visit (log in) to access it. P2P is like friends lending each other cash directly — quick and simple but risky if someone is untrustworthy.

Examcraft 2024 asked: "With respect to data security, why is client-server a good choice?" → Answer: Data stored centrally = easier to apply security controls, encryption, access controls, backups, and audit logs from one location.

🔗 Network Topologies EXAM CALC

A topology is the physical or logical arrangement of computers in a network.

⭐ Star
All devices connect to a central switch/hub. Easy to add devices. If hub fails, all fail.
🚌 Bus
All devices share one backbone cable. Simple & cheap. Cable failure = entire network fails.
💍 Ring
Devices form a circular chain. Data travels one direction. One failure can break whole ring.
🕸️ Mesh
Every node connects to every other. Highly resilient, multiple paths. Expensive to wire.

Formula: n × (n − 1) ÷ 2

📜 What is a Protocol? EXAM

A protocol is a set of standardised rules that computers follow to communicate — governing things like message format, data size, speed, error checking, and timing. Without protocols, computers from different manufacturers couldn't talk to each other.

A protocol is like a shared language combined with manners. When two diplomats meet, they follow a protocol — shake hands, introduce themselves in a set order, speak in an agreed language. Without this, there'd be chaos. TCP/IP is the internet's diplomatic protocol!

Key Protocols — Learn ALL of these!

HTTP
HyperText Transfer Protocol
Transfers web pages between browser and web server. Web pages are in hypertext format.
HTTPS
HTTP Secure
Like HTTP but data is encrypted. Used for banking, shopping, logins. Look for the 🔒 padlock.
FTP
File Transfer Protocol
Sends and receives files to/from a server. Works with all file types.
SMTP
Simple Mail Transfer Protocol
Used to send emails between mail servers.
IMAP/POP3
Mail Retrieval Protocols
Used to receive emails. IMAP keeps email on server; POP3 downloads it.
VoIP
Voice over Internet Protocol
Delivers voice and video calls over the internet (e.g. Zoom, Skype, WhatsApp calls).
TCP
Transmission Control Protocol
Breaks data into packets, numbers them, reassembles at destination, requests re-send of lost packets.
IP
Internet Protocol
Gives every device a unique IP address; routes packets across the internet.

HTTP = Homepages  |  FTP = Files  |  SMTP = Sending email  |  VoIP = Voice  |  TCP = Transport (packets)  |  IP = Identity (address)

DEB papers frequently ask you to fill in a table of protocol names and functions. Also: "Distinguish between IP and VoIP" — IP routes data packets, VoIP delivers real-time voice using that routing system (2025 paper).

📦 The TCP/IP Model (4 Layers) EXAM

When data travels across the internet, it passes through 4 layers. Think of it like sending a package — each layer adds its own envelope and label.

4
Application Layer
Where your apps live. Uses: HTTP, HTTPS, FTP, SMTP, VoIP. This is what the user sees.
3
Transport Layer
Sets up the communication — agrees packet size, checks for errors. Uses: TCP, UDP. Like agreeing the rules of the conversation.
2
Internet (Network) Layer
Addresses and routes packets across the internet. Uses: IP addresses. Like writing the address on your envelope.
1
Data Link Layer (Network Access)
Physical hardware — cables, WiFi, MAC addresses. How data physically travels. Like the van that actually drives the parcel.

Imagine posting a letter. Application Layer = you writing the letter. Transport Layer = putting it in an envelope, numbering pages. Internet Layer = writing the address on the envelope. Data Link Layer = the post van physically driving it there.

What TCP actually does:

  • 1
    Breaks data into equal-sized packets
  • 2
    Assigns sequence numbers so packets can be re-ordered
  • 3
    Adds check digits for error detection
  • 4
    Reassembles packets at destination using sequence numbers
  • 5
    Requests re-transmission of any missing or corrupt packets

TCP = "Trustworthy Courier Parcels" — it tracks every parcel (packet), makes sure they all arrive, and asks for replacements if any are lost! Unlike UDP which just fires and forgets.

📍 IP Addresses, MAC Addresses & DNS EXAM

An IP address is a unique numerical label (e.g. 192.168.1.1) assigned to every device on a network. It identifies WHERE on the internet a device is, so data knows where to go.

A MAC address (Media Access Control) is a permanent, unique hardware address burned into every network card at manufacture. Unlike IP addresses, MAC addresses don't change. Format: 6 pairs of hex digits, e.g. A4:B1:3C:22:F0:9D.

DNS (Domain Name System) is the internet's phone book — it translates human-readable domain names (e.g. www.google.com) into IP addresses (e.g. 142.250.74.46).

IP vs MAC — Key Difference

IP: Changes with location (dynamic). Identifies position on network.

MAC: Never changes. Identifies the physical device.

IP in Cybercrime EXAM

Servers log IP addresses for every connection. Law enforcement can subpoena an ISP to find which customer had a specific IP at a specific time, tracing a suspect's identity and location.

IP address = your home address (can change if you move). MAC address = your fingerprint (always the same, part of you forever). DNS = a sat-nav that translates "McDonald's on O'Connell Street" into GPS coordinates.

DEB 2023 asked: "Why do devices need MAC addresses to connect to the internet?" — MAC addresses identify devices at the hardware level within a local network. Even if IP addresses change, the MAC uniquely identifies the hardware. Also: DEB 2023 asked about DNS as the internet's phone book.

🗄️ Core Database Vocabulary EXAM

A database is an organised collection of structured data, managed by a DBMS (Database Management System). It allows data to be stored, searched, updated, and retrieved efficiently.

A table organises data in rows and columns. A record (row) is a single entry — one person, one book, one transaction. A field (column) is a single attribute of every record — like "Name" or "Date".

Think of a database like a spreadsheet. The whole spreadsheet file = database. Each sheet tab = a table. Each row = a record (one student). Each column = a field (their name, age, etc.).

🔑 Primary Keys & Foreign Keys EXAM

Primary Key (PK)
🗝️ Unique Identifier

A field that uniquely identifies every record in a table. It must be: unique (no two records share the same value) and not null (it can never be empty).

Best choice: a dedicated ID number (e.g. book_id, member_id) rather than a name — names can duplicate!

Foreign Key (FK)
🔗 Table Link

A field in one table that references the primary key of another table. This links the two tables together — it's how relational databases work.

Example: In LOANS, member_id is a FK referencing MEMBERS.member_id.

A primary key is like your passport number — unique to you. A foreign key is like writing your passport number on a hotel register — it links YOU (MEMBERS table) to your BOOKING (LOANS table) without copying all your details again.

🔄 Relational Databases & Data Redundancy EXAM

A relational database stores data in multiple linked tables using keys. This avoids storing the same data in multiple places.

Data redundancy is when the same data is stored unnecessarily in multiple places. This wastes storage and causes inconsistency — if you update one copy but forget another, your data is wrong.

Imagine writing every student's home address in EVERY entry in the school register. If they move house, you'd have to update it in 100 places! A relational database instead stores the address ONCE in a STUDENTS table, and just references the student's ID in other tables. Far more efficient and consistent.

How the LOANS table removes the on_loan field from BOOKS:

If we have a separate LOANS table, we can tell whether a book is on loan simply by checking if that book_id appears in the LOANS table. If it's there = on loan. If not = available. So there's no need to store a redundant on_loan Boolean field in BOOKS — the LOANS table already tells us this information. This is exactly what relational design achieves: avoid storing derived or duplicate data.

"Don't Repeat Yourself (DRY)" — the golden rule of relational databases. Every piece of data should exist in only ONE place. Use foreign keys to link, not to copy.

A hypothesis is an educated, testable prediction about your data. It's a statement you want to prove or disprove. Example (from 2024 exam): "Books published before 1960 are more expensive than books published after 1960." You then collect data and analyse it to test this.

Data cleaning removes errors so your analysis is accurate. Types of errors removed:

  • Missing values — null/empty cells (fill in or remove)
  • Outliers — values far outside expected range that distort averages
  • Inconsistent formats — mixed date/boolean formats (standardise)
  • Duplicates — same record entered twice (remove one)
  • Typos — spelling errors in text fields (fix)

Continuous data can take any value within a range — temperature (30.1°C, 30.12°C, etc.), height, weight. There are infinite possible values between any two points.

Discrete data can only take specific, separate values — number of students (you can't have 2.7 students!), shoe size, number of goals scored.

Memory trick: Discrete = Distinct separate values. Continuous = flows Continuously like a river.

Chapter 9: Modelling & Simulation

Creating simplified virtual versions of real-world systems to test, predict, and explore "what if" scenarios safely.

9

🔬 What is Modelling and Simulation? EXAM

A model is a simplified representation of a real-world system that captures only the most important variables and relationships — ignoring irrelevant details (abstraction).

A simulation is the process of running a model over time to observe behaviour, test scenarios, and predict outcomes. Simulation = model in action.

A model is like a toy plane — it looks like a real plane but is much simpler (no real engine, no passengers). A simulation is putting that toy in a wind tunnel to test what happens. Together they let engineers test designs safely before building the real thing.

✅ Benefits of Modelling

  • Safe — test dangerous scenarios (nuclear, epidemics) without real risk
  • Cheap — no real resources used
  • Fast — compress time (simulate years in seconds)
  • Repeatable — run the same scenario multiple times with different variables
  • "What if" testing — change one variable and observe results

❌ Limitations of Modelling

  • Simplifications may omit key variables
  • Garbage in, garbage out — bad data = bad predictions
  • Can create false confidence in results
  • Real-world complexity is often impossible to fully capture
  • George Box: "All models are wrong, but some are useful."

2025 paper asked: "State one limitation and one benefit of modelling." Also asked for 2 areas where modelling improves outcomes (Education, Mental wellbeing, Environment, Traffic management). Know at least 2 areas with a brief description!

🎨 Abstraction in Modelling EXAM

Abstraction is the process of removing unnecessary details from a model so it only includes variables that are relevant to the outcome being studied. This makes the model simpler, faster, and more useful.

A London Underground map is a brilliant example of abstraction. It shows stations and connections but ignores actual geography, distance between stations, curves of the tunnels, and what's above ground. It removes all the "noise" and shows only what a passenger needs: which line to take and where to change.

🤖 Agent-Based Modelling (ABM) EXAM

Agent-based modelling (ABM) is a type of simulation where each individual entity (an agent) is programmed with simple rules. The simulation runs all agents simultaneously and observes how their interactions produce complex system-level outcomes.

Emergent behaviour is complex, system-level patterns that arise from many simple individual interactions — these patterns are not directly programmed, they just emerge naturally from the interactions of agents following their rules.

Think of a murmuration of starlings — thousands of birds swirling in amazing coordinated patterns. Nobody is giving orders. Each bird follows 3 simple rules: don't collide, stay close to neighbours, match their direction. The beautiful swirling patterns emerge from those simple individual rules. That's emergent behaviour!

Real-World ABM Examples:

🚗
Traffic Flow
Each car = an agent. Rules: follow speed limit, brake if car ahead slows. Emergent: traffic jams form even with no accidents — just from individual braking decisions.
🦠
Disease Spread
Each person = an agent with state (susceptible/infected/recovered). Rule: become infected if near an infected agent. Emergent: infection waves, herd immunity thresholds.
🐜
Ant Colony
Each ant = an agent following pheromone trails. Emergent: efficient foraging paths emerge — ants find the shortest route to food without a central planner.
📈
Stock Market
Each trader = an agent. Rules: buy when price drops, sell when it rises. Emergent: market crashes, bubbles, and boom-bust cycles emerge from individual trading decisions.

Disease Spread ABM — 2025 Exam Question in Detail:

  • 1
    Each person in the school = one agent. Each agent has a state: Susceptible, Infected, or Recovered.
  • 2
    Simple rules programmed in: a susceptible agent becomes infected if it is close to an infected agent for a certain amount of time.
  • 3
    The simulation runs in time-steps (e.g. each step = 1 hour of school). At each step, agents move and interact based on their rules.
  • 4
    Emergent behaviours observed: infection waves, clustering around classrooms, herd immunity when enough agents are recovered.
  • 5
    Test strategies: Add a "mask rule" (reduces transmission probability) or a "vaccination rule" (starts some agents immune). Measure success by comparing infection rates.

DEB 2024 asked: "Name a scenario for ABM and explain benefits." DEB 2023 used traffic. 2025 paper used disease spread. Know: (i) define ABM (ii) define emergent behaviour (iii) describe how ABM works for a specific scenario (iv) name one strategy to test and how to measure success.
